## Phase 2 — Delta Analysis: Three-Tier Algorithm

**Purpose**: Provide accurate, scalable delta traces that match official FIA timing regardless of
telemetry quality.

**Logic**: Telemetry sampling rates vary; a tiered approach automatically selects the best available
method. Tier 1 uses RelativeDistance (0-1 normalized position) with time pre-scaling to guarantee
delta[-1] equals official_gap. Lower tiers degrade gracefully when data is incomplete.

**Implementation**: Added _calculate_with_relative_distance() as Tier 1 (confidence >=0.9),
_calculate_with_time_only() as Tier 2 (~0.8), speed integration as Tier 3 (<=0.6). Extended FastF1
client to extract RelativeDistance and Time fields, propagated through API DTO to delta_analysis.

## Phase 3 — Corner Analysis: Confidence Improvements + Straight-Line Integration

**Purpose**: Improve corner analysis confidence levels through three targeted fixes, and close the
reconciliation gap where corner totals didn't match official timing.

**Confidence Improvements**: Before the fixes, confidence distributions were low-dominated across
most circuits, with occasional medium or high results depending on corner characteristics. We
implemented three distinct changes that work together:

1. **Off-by-one bug fix** (lines 277-281): The brake gradient array measures change FROM index i
   TO i+1, but the original code checked brake threshold at index i against gradient[i]. Fixed by
   checking zone_brake[i+1] against gradient[i] to correctly detect when brake reaches threshold
   with sufficient gradient leading into it.

2. **V2 deceleration-based detection**: FastF1's brake pressure signal is often boolean-like
   (0 or 100). The V2 algorithm uses physics-based deceleration: a = (v2^2 - v1^2) / (2 * delta_d),
   detecting braking zones by actual speed reduction rather than unreliable pressure data.
   Implemented in detect_braking_zone_v2() with configurable deceleration thresholds.

3. **Delta accuracy confidence boost**: Added _boost_confidence_from_delta_accuracy() function
   that leverages the 100% accurate scaled delta trace. When delta_scaling_factor is approximately 1.0
   (Tier 1) and delta_confidence >= 0.95, corner confidence is boosted from low to medium—because
   even if zone boundaries have +/-10m uncertainty, the delta values within that zone are
   mathematically correct.

After implementation, distributions shifted toward medium and high confidence for corners with
clear braking events, while circuits with complex throttle/brake overlap may still produce mixed
results—this variation is expected given external factors we cannot fully control.

**Straight-Line Integration**: Users previously asked "corners show +0.2s but the gap is +0.5s—
where's the other +0.3s?" Straight-line segments between corners now capture this missing delta,
providing full lap accountability with mathematical reconciliation.

**Implementation**: 
- Implemented analyze_corners_v2() with deceleration-based braking zone detection
- Added _boost_confidence_from_delta_accuracy() for delta-aware confidence boosting
- Added StraightSegment and LapBreakdown dataclasses
- Added calculate_straight_segments() and calculate_lap_breakdown() with 5ms reconciliation tolerance
- Added sanity checks hiding analysis when scale factors are extreme or corner deltas exceed +/-0.5s

## Phase 4 — Technique Profiling: 5th Dimension

**Purpose**: Extend the 4-dimension technique profile (braking, apex, exit, consistency) with
straight-line performance to explain setup trade-offs and aero characteristics.

**Logic**: Straight-line delta is inverted (negative = faster = STRONG). Session-relative percentiles
ensure classification adapts to competitive context. Primary factor attribution distinguishes
aero efficiency from exit traction based on segment characteristics.

**Implementation**: Added StraightLineDimension dataclass with percentile, primary_factor, and
top gaining/losing straights. Added determine_straight_line_primary_factor() (priority: top_speed
then exit_correlation then segment_factors), aggregate_straight_line_performance(), and
classify_straight_line_dimension(). Extended profile_drivers() to produce 5-dimension profiles.

## Phase 5 — Insight Generation: Straight-Line Templates

**Purpose**: Generate human-readable explanations for the 5th dimension following anti-hallucination
principles (template-based, data-bound, no LLM generation).

**Logic**: Dual-mode output serves engineers (metrics-heavy) and drivers (action-oriented). Cross-
dimension analysis (exit x straight) reveals setup anomalies and technique opportunities.

**Implementation**: Added STRAIGHT_LINE_ENGINEER/DRIVER, PRIMARY_FACTOR, LAP_BREAKDOWN, and
EXIT_STRAIGHT_OPPORTUNITY template sets. Added generate_straight_line_insight(),
generate_lap_breakdown_insight(), and generate_exit_straight_opportunity().

## Phase 6 — API Orchestration: track_length Flow

**Purpose**: Enable the 5th dimension by propagating track_length from Track Intelligence through
the entire stack to corner analysis.

**Logic**: Without track_length, straight segments cannot be calculated (no way to identify the
gap from last corner to start/finish). Graceful degradation returns null for 5th dimension fields
while preserving all other analysis.

**Implementation**: Added track_length to PerformanceInsightsConfig and Pydantic schemas. Added
LapBreakdownSchema, StraightSegmentSchema, and serialization helpers. Wired track_length through
run_phase3_corner() to analyze_corners_v2().

**Root Cause Resolved**: track_length not propagated — lap_breakdown silently returned null.
