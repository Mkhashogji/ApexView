--- Corner Names (24 circuit files) ---

Added validated corner names to all 24 track JSON files. The Corner
Analysis component displayed dashes because the data files had no name
values — the rendering code was already built, the gap was in the data.
Five circuits had unverified names removed, seven were populated from
scratch, twelve were audited and corrected. Five circuits required
physical feature mapping (matching corners by type and distance rather
than turn number when sources use different numbering for the same
physical location).

--- Qualifying — Race Condition Fix ---

Fixed a bug where Corner Analysis did not update when switching GPs.
Two hooks ran concurrently: one fetching track corners, one using those
corners to request analysis. Both used keepPreviousData (shows old data
while loading to prevent blank screens), so the analysis hook received
stale corners from the previous circuit and sent them to the backend.
Fix: the analysis query now waits until track data is genuinely fresh
via React Query's isPlaceholderData flag.

--- Weekend Selector — Persistence Across All Pages ---

The Race Weekend Selector allows users to choose which GP weekend to
analyse. The selected round and season are stored as URL search
parameters (e.g. ?round=1&season=2025), and a shared mechanism in the
Navigation component forwards these parameters when the user clicks
between pages, so the selection persists during navigation.

This was implemented first for the Qualifying, Race, and Practice
pages, which share the same pattern of reading round/season from the
URL to load session-specific data. However, the Home page and Track
Intelligence page were not included in this forwarding set, meaning
the parameters were stripped when navigating to either page, causing
the selector to reset to the default Abu Dhabi GP.

Fix: expanded the ANALYSIS_PAGES set to include all five pages (Home,
Qualifying, Race, Practice, Track Intelligence). Updated the logo
link in the navigation bar to also forward parameters. On the Home
page, the feature cards (which link to each analytical page) were
updated to read the current URL parameters and append them to their
destination links, ensuring the selection carries through even when
navigating via the Home page rather than the navigation bar.

--- Analysis Service Rename ---

Renamed "ML Service" to "Analysis Service" across the entire codebase.
The rename applies specifically to the telemetry analysis pipeline
(the service responsible for qualifying analysis: delta computation,
corner detection, technique profiling, and insight generation). That
pipeline's implementation consists of physics-based computation,
rule-based signal processing, descriptive statistics, and template-based
text generation — methods that do not constitute machine learning by
standard technical definition, despite being originally labelled as
such.

The broader codebase does include statistical modelling: the Race
page's tyre degradation component uses linear regression
(scipy.stats.linregress) to fit a model of tyre age against lap time,
producing a degradation rate and R² goodness-of-fit metric. That
component resides in the API service and was not part of this rename
— it was already accurately described.

The rename covers folders, Docker service, API routes, env vars, hooks,
types, UI badges, loggers, and ~35 documentation files. No logic or
behaviour changes — naming corrections only.
